# Runbook: Escalate a support ticket

Goal: every ticket reaches the right person once, without being bounced around.
When to use: a customer writes in through Intercom.
Owner: Jonas Berg.

## Steps

1. Read the ticket in Intercom. Jonas owns it first.
2. If you can answer it yourself, answer it. If it is the second time you answer this question, add the answer to the brain (team rule 2).
3. If the product behaves wrongly, hand it to Ana Silva (technical support).
4. If production is down or broken for customers, it is an incident: hand it to Noor Haddad (on call).
5. If it involves customer data in any way, hand it to Ivan Petrenko. Do not copy the data into the ticket notes, Slack or an AI tool (team rule 3).

## If something goes wrong

1. Not sure whether it is technical or an incident: GAP, ask Noor (see `customers/support-escalation.md`).
2. Ghost shift complaints are the most common: GAP, no standard answer yet. Ask Jonas or Ana and write it down.

## Done when

The ticket sits with the one person who can solve it.
